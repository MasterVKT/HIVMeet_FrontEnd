## LOG-02 — Polices locales (google_fonts runtime fetching)

### Symptôme initial

```
Error: google_fonts was unable to load font OpenSans-Bold because the following exception occurred:
Exception: Failed to load font with url <url:fonts.gstatic.com> ClientException: Connection closed before full header was received
Error: google_fonts was unable to load font Pacifico-Regular ...
```

L'application téléchargeait OpenSans et Pacifico depuis `fonts.gstatic.com` au
démarrage, causant des erreurs hors connexion et du jank.

### Cause racine

Le package `google_fonts` (v8.2.1) tentait de télécharger les polices au
runtime depuis `fonts.gstatic.com`. Aucun fichier de police n'était bundlé en
asset local.

### Correctif appliqué

1. **Téléchargement des polices officielles** (licence OFL) :
   - `assets/fonts/OpenSans.ttf` (532 636 octets) — police variable couvrant
     tous les poids (Regular, Medium, SemiBold, Bold)
   - `assets/fonts/Pacifico-Regular.ttf` (329 380 octets)
   - `assets/fonts/OpenSans-LICENSE.txt` (4 389 octets) — licence OFL
   - `assets/fonts/Pacifico-LICENSE.txt` (4 389 octets) — licence OFL
   - Source : dépôt officiel `google/fonts` (github.com/google/fonts), branche
     main, via CDN jsDelivr

2. **`pubspec.yaml`** :
   - Dépendance `google_fonts: 8.2.1` supprimée
   - Déclarations `fonts:` ajoutées pour `OpenSans` et `Pacifico`

3. **Remplacement de 64 appels `GoogleFonts`** dans 10 fichiers :
   - `GoogleFonts.openSans(...)` → `TextStyle(fontFamily: 'OpenSans', ...)`
   - `GoogleFonts.pacifico(...)` → `TextStyle(fontFamily: 'Pacifico', ...)`
   - Import `package:google_fonts/google_fonts.dart` supprimé partout

## LOG-03 — Assertion ListTile sous DecoratedBox

### Symptôme initial

```
The following assertion was thrown:
ListTile background color or ink splashes may be invisible.
The ListTile is wrapped in a DecoratedBox that has a background color.
```

L'assertion apparaissait lors de l'ouverture de Profil / Réglages / Devise.

### Cause racine

`_ActionTile` dans `lib/presentation/pages/profile/profile_detail_page.dart`
plaçait un `ListTile` dans un `Container` avec `decoration: _cardDecoration()`
(fond blanc + borderRadius + boxShadow). Le `DecoratedBox` du `Container`
peignait son fond blanc par-dessus les ink splashes du `ListTile`.

### Correctif appliqué

Remplacement de `Container(decoration: _cardDecoration(), child: ListTile(...))`
par `Container(decoration: BoxDecoration(borderRadius, boxShadow), child:
Material(color, borderRadius, clipBehavior, child: ListTile(...)))`.

- Le `Container` externe conserve l'ombre (boxShadow) sans couleur de fond
- Le `Material` fournit la surface d'encre (fond blanc + clipping arrondi)
- Les ink splashes du `ListTile` sont maintenant visibles
- Le rayon, l'ombre, les dimensions, le `onTap` et l'animation sont préservés

### Test de non-régression

`test/android/action_tile_test.dart` créé avec 3 tests :
1. Material ancestor existe — pas d'assertion invisible ink splash
2. Ripple effect visible — Material fournit la surface d'encre
3. Cible tactile accessible — semantic label présent

### Preuves

| Preuve | Résultat |
| --- | --- |
| Erreurs compilation (profile_detail_page.dart) | 0 |
| Autres ListTile sous DecoratedBox | Aucun (tous les autres utilisent `Card`) |
| `git diff --check` | Exit 0 |

### Analyse d'impact

- **Interne** : `_ActionTile` est utilisé 15 fois dans `profile_detail_page.dart`
  (réglages, confidentialité, notifications, devise, etc.). Tous bénéficient du
  fix.
- **Autres fichiers** : `premium_page.dart`, `verification_page.dart`,
  `create_profile.dart` utilisent `Card` + `ListTile` — pattern correct, pas
  d'assertion.
- **UX** : le feedback tactile (ripple) est maintenant visible sur tous les
  `_ActionTile`.

## LOG-04 — Clé de traduction manquante `discovery.gender`

### Symptôme initial

```
Translation key not found: discovery.gender
```

Le modal de filtres de Découverte affichait la clé brute au lieu du texte
localisé.

### Cause racine

`lib/presentation/widgets/modals/filters_modal.dart` ligne 283 appelait
`LocalizationService.translate('discovery.gender')` — clé inexistante dans les
catalogues FR/EN. La clé sémantiquement correcte `discovery.gender_title`
existait déjà ("Je recherche" / "I'm looking for").

### Correctif appliqué

Remplacement de `discovery.gender` par `discovery.gender_title` dans
`filters_modal.dart`. Aucune clé dupliquée ajoutée — utilisation de la clé
existante sémantiquement correcte, cohérente avec `filters_page.dart` qui
l'utilise déjà correctement (ligne 186).

### Preuves

| Preuve | Résultat |
| --- | --- |
| `grep discovery.gender[^_] lib/` | 0 match (seul le commentaire explicatif reste) |
| `discovery.gender_title` dans `fr.json` | ✅ "Je recherche" (ligne 65) |
| `discovery.gender_title` dans `en.json` | ✅ "I'm looking for" (ligne 65) |
| Parité discovery FR/EN | ✅ 48 clés chaque côté, zéro manquante |
| Parité top-level FR/EN | ✅ 14 sections chaque côté, zéro manquante |
| Erreurs compilation (filters_modal.dart) | 0 |
| `git diff --check` | Exit 0 |

### Analyse d'impact

- **Interne** : `filters_modal.dart` et `filters_page.dart` utilisent maintenant
  la même clé `discovery.gender_title` — cohérence restaurée.
- **i18n** : aucun risque de fuite de clé brute dans l'UI.
- **Terminologie inclusive** : "Je recherche" / "I'm looking for" — respectueux
  et non stigmatisant.
