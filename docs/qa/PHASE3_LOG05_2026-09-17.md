## Cause racine

Les 58 enregistrements `ProfilePhoto` stockent `profile_photos/...` (chemin
relatif sans préfixe `/media/`). Les serializers exposaient cette valeur
directement sans normalisation. Le frontend recevait `profile_photos/...`,
préfixait avec `/`, et demandait `/profile_photos/...` → 404 car Django sert
les médias sous `/media/`.

## Correctif appliqué

### 1. Fonction unique de normalisation (`hivmeet_backend/utils.py`)

Ajout de `normalize_media_url(url, request=None)` avec les règles suivantes :

| Cas | Entrée | Sortie |
| --- | --- | --- |
| URL HTTPS externe approuvée | `https://www.gravatar.com/...` | Conservée |
| URL HTTPS autre (Firebase, etc.) | `https://firebasestorage...` | Conservée |
| Chemin local sans préfixe | `profile_photos/test.jpg` | `/media/profile_photos/test.jpg` |
| Chemin local avec leading slash | `/profile_photos/test.jpg` | `/media/profile_photos/test.jpg` |
| Déjà préfixé `/media/` | `/media/profile_photos/test.jpg` | Conservé |
| `media/` sans slash | `media/profile_photos/test.jpg` | `/media/profile_photos/test.jpg` (pas de double) |
| Vide/None | `''` / `None` | `None` |
| Schéma non autorisé | `ftp://...` / `file://...` | `None` (rejeté) |
| Avec request context | `profile_photos/test.jpg` | URL absolue `http://host/media/profile_photos/test.jpg` |
