**LOG-09 — Erreurs de compilation Dart dans 3 fichiers de test (phases 1/3/4)**

- **Symptôme :** `flutter analyze --no-pub` → 19 problèmes (8 bloquants) dans
  `test/android/action_tile_test.dart`, `test/android/fcm_retry_test.dart`,
  `test/android/version_code_test.dart`. Ces fichiers n'avaient jamais été réellement
  compilés/exécutés (créés pendant le blocage SDK).
- **Cause racine :** API `Color.withValues` appelée avec argument positionnel au lieu
  de nommé ; chaîne littérale mal échappée (`n\\'est` au lieu de `n'est`) ; getter
  `String.isEmpty` invoqué comme méthode (`.isEmpty()`) ; comparaison `== null` sur
  type non-nullable ; `Finder` `Material` ambigu (plusieurs ancêtres Material via
  `MaterialApp`/`Scaffold`).
- **Correctif :** 3 fichiers de test corrigés (voir diff), aucun fichier de production
  touché.
- **Test :** `flutter analyze --no-pub` → 0 issue ; `flutter test --no-pub` sur les 3
  fichiers → 11/11 verts ; suite complète (53 fichiers, 283 tests, 1 skip) → 0 échec.
- **Résultat :** PASS.
- **Impact :** aucun (fichiers de test uniquement).

**LOG-10 — Build profile incapable d'atteindre le backend de recette**

- **Symptôme :** après connexion sur les 2 appareils avec un APK profile, message
  « Service Indisponible ».
- **Cause racine double :**
  1. Backend de recette arrêté (confirmé par `curl` : connexion refusée).
  2. **Défaut applicatif** : `lib/core/config/app_config.dart`, méthode `apiBaseUrl` —
     la sélection d'URL testait uniquement `kDebugMode`. En mode `profile`,
     `kDebugMode` est faux, donc **tout build profile retombait sur l'URL de
     production** (`https://api.hivmeet.com`) au lieu du backend LAN de recette,
     quel que soit l'état du backend. Ce défaut bloquait structurellement toute
     mesure de performance en profile.
- **Correctif :** `app_config.dart` — condition étendue à `kDebugMode || kProfileMode`
  (détection physique/émulateur + sélection d'URL), pour que le mode profile utilise
  le même backend LAN que le mode debug. Comportement release/production inchangé
  (ni `kDebugMode` ni `kProfileMode` n'y sont vrais).
- **Test :** `flutter analyze --no-pub` ciblé → 0 issue. Validation fonctionnelle
  réelle : connexion réussie sur les 2 appareils après rebuild (voir §2).
- **Résultat :** PASS.
- **Impact :** aucun sur release/production ; débloque toute mesure profile future.

**Incident réseau annexe — téléchargement des artefacts moteur Flutter**

Deux tentatives de build profile universel (3 ABI) ont échoué par timeout réseau
(`storage.googleapis.com`, ~76 min cumulées) ; deux tentatives scopées (arm64+x64)
ont également échoué (~19 min cumulées), même cause. `android/gradle.properties`
contenait déjà des `systemProp.http(s).*timeout` (Java `URLConnection`, sans effet
sur le transport de dépôt interne de Gradle). Ajout des propriétés Gradle réelles
(`systemProp.org.gradle.internal.http.*timeout`,
`systemProp.org.gradle.internal.repository.max.retries/initial.backoff`) → build
réussi. Classé comme correctif d'infrastructure de build, aucun impact produit.

## 3. Limite de méthode : `dumpsys gfxinfo` non applicable à cette app

Tentative de mesure des percentiles de frame (`Janky frames`, 50/90/95/99e
percentile) via `dumpsys gfxinfo <pkg>` autour des scénarios swipe : **« Total
frames rendered: 0 »** de façon systématique, malgré un rendu visuellement actif et
confirmé par capture d'écran. Cause probable : le moteur de rendu Flutter
(pipeline Impeller / surface de rendu externe) ne transite pas par le pipeline
HWUI par-vue qu'instrumente `dumpsys gfxinfo` — limitation d'outillage connue sur
les applications Flutter modernes, **pas un défaut applicatif**. Une mesure
Timeline DevTools réelle (`flutter attach` / `--trace-startup`) serait nécessaire
pour des percentiles de frame fiables ; jugée hors budget pour cette session et
reportée (décision utilisateur explicite).

**Conséquence sur le verdict :** la preuve quantitative de frame-jank par scénario
n'est pas disponible avec les outils utilisés ; la preuve qualitative (recette
visuelle réelle, aucun gel/saut perceptible, cold start mesuré fiable) est en
revanche complète et réelle.
