## Symptôme initial

```
adb: failed to install ...app-debug.apk: Failure [INSTALL_FAILED_VERSION_DOWNGRADE]
```

L'APK produit avait un `versionCode=1` inférieur ou égal au package déjà
installé sur les deux appareils, provoquant le refus d'installation par Android.

## Cause racine

**Confirmée** : `android/local.properties` (fichier local ignoré par Git) figeait
`flutter.versionCode=1`. Le `build.gradle` utilisait cette valeur avec un
fallback `'1'`. Aucun workflow CI n'existait pour appliquer une règle monotone.

Le `local.properties` étant ignoré par Git (`.gitignore` ligne 58), cette valeur
n'était pas reproductible entre environnements et ne pouvait pas garantir la
monotonie du `versionCode` entre builds.

## Correctif appliqué

### 1. `android/app/build.gradle`

Nouvelle logique de calcul du `versionCode` avec trois sources priorisées :

1. **`HIVMEET_VERSION_CODE`** (variable d'environnement CI) — priorité la plus
   haute pour les pipelines d'intégration.
2. **`flutter.versionCode`** dans `local.properties` — override local explicite
   (mais la valeur `1` est rejetée pour éviter le downgrade).
3. **Nombre de commits Git** (`git rev-list --count HEAD` + base 1000) — fallback
   monotone par construction, reproductible depuis n'importe quel checkout propre.

La valeur `1` est explicitement rejetée pour déclencher le fallback Git, car
c'est la valeur qui causait le downgrade.

### 2. `android/local.properties`

Ligne `flutter.versionCode=1` supprimée et remplacée par un commentaire
expliquant la nouvelle logique. La ligne est gardée commentée pour permettre un
override explicite si nécessaire.

### 3. `.github/workflows/android-build.yml`

Workflow GitHub Actions créé pour :
- Calculer le `versionCode` monotone en CI (`1000 + git rev-list --count HEAD`)
- Vérifier que le `versionCode` est strictement supérieur à 1
- Construire l'APK debug avec `HIVMEET_VERSION_CODE`
- Vérifier les métadonnées de l'APK produit (versionCode correspond)
- Calculer et publier le checksum SHA-256 de l'APK
- Uploader l'APK comme artefact

### 4. `test/android/version_code_test.dart`

Test de non-régression validant :
- Le versionCode de fallback (base 1000) est toujours > 1
- `local.properties` est ignoré par Git
- Le versionCode calculé depuis les commits Git est monotone
- Un versionCode de "1" est explicitement rejeté par la logique
